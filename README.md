# 당신의 술잔에 독배를 — 밸런스 테스트 프로토타입

두 대의 컴퓨터로 실제 플레이하며 밸런스를 검증하기 위한 웹 기반 2인 프로토타입입니다.
장남 / 차남, 두 왕자가 서로의 처소에 독배를 몰래 심고, 각자의 처소에서 술잔을 고르며
10라운드 동안 점수를 겨루는 궁중 암투극입니다.

> 같은 와이파이가 아니어도 각자 컴퓨터에서 URL 하나로 접속하게 만들고 싶다면
> **`DEPLOY.md`**를 먼저 보세요 (무료 호스팅에 올려 진짜 웹사이트로 만드는 단계).
> 아래 "실행 방법"은 같은 네트워크의 두 컴퓨터로 바로 테스트하는 로컬 실행법입니다.

## 실행 방법 (한 대가 서버 역할)

1. 두 컴퓨터가 같은 네트워크(같은 와이파이/공유기)에 연결되어 있어야 합니다.
2. **서버를 실행할 컴퓨터 한 대**에서:
   ```bash
   npm install
   node server.js
   ```
   실행하면 콘솔에 `http://localhost:3000` 및 해당 컴퓨터의 사설 IP 안내가 출력됩니다.
   (IP를 못 찾으면 Mac/Linux는 `ifconfig`, Windows는 `ipconfig`로 확인하세요. 보통
   `192.168.x.x` 형태입니다.)
3. **서버를 실행한 컴퓨터**의 브라우저에서 `http://localhost:3000` 접속 → 먼저 접속한 쪽이 **장남**이 됩니다.
4. **다른 컴퓨터**의 브라우저에서 `http://<서버 컴퓨터의 IP>:3000` 접속 → **차남**이 됩니다.
5. 둘 다 접속하면 자동으로 셋업(독 설치) 단계가 시작됩니다.

한 대의 컴퓨터에서 혼자 테스트하려면, 브라우저 창 2개(또는 시크릿 창 1개 추가)를 열어
둘 다 `http://localhost:3000`으로 접속해도 됩니다.

## 밸런스 조정 (환경변수)

숫자를 바꿔가며 빠르게 테스트할 수 있도록, 주요 수치는 실행 시 환경변수로 덮어쓸 수 있습니다.

```bash
ROUNDS=6 POISON_PENALTY=2 NIM_LIMIT=21 node server.js
```

바꿀 수 있는 값(기본값은 `server.js` 상단 `CONFIG` 참고): `ROUNDS`(총 라운드 수, 기본 10),
`POISON_PENALTY`(종료 시 무효화되지 않은 독 1개당 감점, 기본 -3), `ANTIDOTE_NEED`(해독제
몇 개당 독 1개 무효화), `GOLD_PTS`/`SILVER_PTS`(금·은 술잔 점수), `INVENTORY_CAP`(아이템
보관 한도), `NIM_LIMIT`(독배 채우기 한도), `BOMB_FUSE_MIN`/`MAX`(폭탄 퓨즈 범위),
`PIN_POP_MIN`/`MAX`(안전핀 팝 범위), `CARD_MAX`(거짓 카드 숫자 범위), `BANK_DIGITS`(금고
번호 자릿수), `REWARD_FLASH_MS`(섬광 정찰 보상의 사용 제한 시간, ms).

## 게임 흐름 요약

1. **셋업**: 서로 상대방 처소의 6×6 그리드 중 3칸에 독 술잔을 몰래 지정합니다.
2. **본게임 (총 10라운드 고정)**: 매 라운드마다
   - 이번 라운드의 **보상**이 먼저 공개됩니다 (4종 중 무작위 1개 — 섬광 정찰 / 한 칸 정찰 /
     행 정찰 / 열 정찰). 미니게임 승자가 이 보상을 가져갑니다.
   - 미니게임 1판 진행 (10종이 매치마다 셔플되어 라운드당 서로 다른 종류로 등장합니다:
     독배 채우기 · 독 든 손 맞히기 · 거짓 카드 건네기 · 폭탄 눈치 넘기기 · 안전핀 뽑기 배팅 ·
     표식 대결 · 촛불 개수 맞히기 · 숫자 합 홀짝 · 배짱 대결 · 금고 번호 맞추기)
   - 행동 순서는 미니게임 승패와 무관하게 **라운드 홀/짝으로 고정 교대**합니다(장남↔차남,
     5:5 공평). 순서대로 각자 자기 처소에서 행동 1개 선택: 아이템 얻기(4종 중 택1) /
     단서 얻기(4종 카테고리 중 택1, 정확한 좌표·행·열·구역·인접 중 무작위로 정보 공개,
     같은 단서는 연속으로 나오지 않음) / 술잔 고르기(칸을 열어 즉시 효과 적용)
   - 미니게임 승자는 그 라운드 중 아무 때나 보상을 사용할 수 있습니다(섬광 정찰은 보상을
     받은 시점부터 실시간 제한시간 있음, 나머지 3종은 제한시간 없이 그 라운드 안에서만 유효).
3. **종료**: 10라운드가 끝나면 각자 "술잔 점수(금+2·은+1 누적) − 독 개수 × 3"으로 최종
   점수를 계산해 더 높은 쪽이 승리합니다. **독을 마셔도 즉시 패배하지 않습니다** — 해독제로
   무효화하지 못한 독은 감점으로만 반영됩니다.

## 라운드 보상 4종

- **섬광 정찰**: 보상을 받은 뒤 1분 안에 원하는 순간, 상대 처소 전체를 0.1초간 공개
- **한 칸 정찰**: 상대 처소에서 원하는 칸 1개의 정체를 확인
- **행 정찰**: 상대 처소의 원하는 행에서, 지정한 술잔 종류가 몇 개 있는지 확인
- **열 정찰**: 상대 처소의 원하는 열에서, 지정한 술잔 종류가 몇 개 있는지 확인

## 아이템 4종

- **은수저**: 칸 1개를 열지 않고 독 여부만 확인
- **소믈리에의 코**: 행 또는 열 하나의 독 개수만 확인
- **해독의 부적**: 장착 후 다음 독 1회를 자동 무효화
- **잔 바꿔치기**: 상대의 다음 단서 결과를 조작(상대는 조작 여부를 알 수 없음)

## 자동 시뮬레이션 테스트 (개발용)

`test_sim.js`는 두 개의 가상 클라이언트가 무작위로 플레이하며 서버 로직에 예외가
없는지, 10종 미니게임과 4종 보상이 모두 정상 동작하는지, 10라운드 종료 후 점수
비교가 올바르게 이루어지는지 확인하는 자동 테스트입니다. 서버를 먼저 켜둔 상태에서
실행하세요.

```bash
node server.js            # 터미널 1
node test_sim.js          # 터미널 2 (socket.io-client 필요: npm install 시 devDependency로 함께 설치됨)
```

## 알려진 한계 / 다음 확인 사항 (검증자 메모)

- **즉사 → 감점 전환의 텐션 변화**: 기존에는 독배 3개 = 즉시 패배였지만, 이번 개편으로
  독은 종료 시 -3점 감점으로만 반영됩니다. "죽는다"는 공포감이 "점수가 깎인다"는 계산적
  긴장감으로 바뀐 것이므로, 실제 플레이테스트에서 쫄깃함이 유지되는지 확인이 필요합니다.
- **섬광 정찰의 완전한 보안은 프로토타입 한계**: 서버는 0.1초만 전체 데이터를 클라이언트에
  보내고 화면에서 지우지만, 브라우저 개발자도구 등으로 우회하면 이론상 확인이 가능합니다.
  일반적인 플레이 환경에서의 "훔쳐보기 방지" 수준으로 설계된 것이며, 완전한 보안은 아닙니다.
- **행동 순서 고정 교대의 트레이드오프**: 미니게임 승패가 더 이상 행동 순서에 영향을 주지
  않으므로(보상이 그 역할을 대체), 미니게임에서 계속 지더라도 행동 순서상 불리해지지는
  않습니다. 다만 그만큼 정찰 정보 격차는 누적될 수 있습니다.
- **잔 바꿔치기 피드백 부재**: 상대가 이 아이템에 당했을 때 알아챌 방법이 없습니다
  (의도된 설계지만, 플레이테스트 중에는 "뭔가 이상하다"는 느낌조차 없어 아이템의
  존재감이 약할 수 있습니다).
- **폰트**: 구글 폰트(Noto Sans KR 본문 / Nanum Myeongjo 제목)를 온라인에서 불러옵니다.
  오프라인 환경이면 기본 고딕체로 자동 대체되며 기능에는 영향이 없습니다.
- 지금은 재접속(reconnect) 시 이전 진행 상황을 복구하지 않습니다. 접속이 끊기면
  관리자 버튼("전체 초기화")으로 새로 시작해야 합니다 — 프로토타입이라 우선 단순하게
  구현했습니다.
